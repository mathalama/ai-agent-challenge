# Онлайн-заявка на потребительский кредит

Техническое задание на цифровой канал оформления беззалоговых кредитов в розничном банке.

---

## Часть 1. Бизнес-требования и сценарии

### Паспорт документа

| Поле | Значение |
| :--- | :--- |
| **Проект** | Цифровое кредитование физических лиц |
| **Канал** | Веб-портал и мобильный кабинет |
| **Заказчик** | Департамент розничного кредитования |
| **Версия и дата** | — |
| **Идентификатор инициативы** | FIN-LOAN-2026 |

### Цель доработки
Обеспечить подачу и предварительное скоринговое рассмотрение заявки на потребительский кредит без визита в отделение.

### Бизнес-правила
* **КР-1.** Заявитель — гражданин РК в возрасте от 21 до 65 лет на момент подачи заявки. Допустимый диапазон суммы: от 100 000 до 7 000 000 ₸ на срок от 6 до 60 месяцев.
* **КР-2.** При получении отказа по скорингу клиент не может подавать повторную заявку в течение 30 календарных дней с даты отказа.
* **КР-3.** Долговая нагрузка рассчитывается по подтверждённому ежемесячному доходу за последние 6 месяцев. При неполных данных за период заявка отклоняется автоматически.
* **КР-4.** Расчёт графика платежей ведётся по аннуитетной схеме с начислением процентов по номинальной годовой ставке.
* **КР-5.** Если клиент уменьшил запрашиваемую сумму не менее чем на 20 % или увеличил срок, система допускает немедленную повторную подачу заявки на следующий день после отказа без ожидания окончания моратория.

### Взаимодействие компонентов
Клиентский интерфейс → шлюз заявок → скоринговый движок → бюро кредитных историй. Шлюз передаёт в сервис уведомлений ИИН заёмщика, номер удостоверения личности и размер официального дохода для формирования SMS и e-mail с решением.

### Производительность и надёжность
Скоринговый конвейер должен выносить предварительное решение достаточно быстро и стабильно работать при сезонных пиках обращений.

### Модель хранения данных
В базе данных заявок хранятся идентификатор клиента, запрашиваемая сумма в тенге, срок в месяцах и одобренная процентная ставка в базисных пунктах (`rate_bp`), тогда как в расчётном ядре и клиентском API ставка передаётся в годовых процентах.

## Часть 2. Контракт внешнего API

Спецификация конечной точки регистрации новой кредитной заявки.

### Реквизиты метода

| Поле | Значение |
| :--- | :--- |
| **Назначение** | Регистрация и отправка заявки на скоринг |
| **HTTP-метод** | GET |
| **Аутентификация** | OAuth 2.0 Bearer |
| **Путь (Stage / Prod)** | Stage: `/api/v1/loans/submit` ; Prod: TBD |
| **Документация OpenAPI** | отсутствует |
| **Сервис** | LoanOriginationGateway |

### Пошаговый алгоритм
1. Проверить валидность токена клиента и статус блокировки учётной записи.
2. Сверить параметры суммы и срока с ограничениями продукта.
3. Зафиксировать заявку в хранилище и запустить асинхронный скоринг.
4. При нарушении лимитов вернуть код ответа 201 с полем `decision: "REJECTED_INPUT"`.

### Входные параметры

#### Параметры строки запроса

| Поле | Тип | Ограничения | Обязательность | Описание | Колонка БД |
| :--- | :--- | :--- | :--- | :--- | :--- |
| `iin` | string | 12 цифр | Да | ИИН заёмщика | `client_iin` |
| `principal` | integer | 100 000–7 000 000 | Да | Запрашиваемая сумма в тенге | `principal_kzt` |
| `termMonths` | integer | 6–60 | Да | Срок кредита в месяцах | `term_months` |

#### Тело запроса
* **Content-Type:** `application/json`
* Для метода тело запроса не передаётся.

### Структура ответа
Коды 200 и 201 означают успешное создание заявки. Коды 4xx и 5xx возвращаются при ошибках проверки и сбоях сервиса.

| Поле | Тип | Условие | Описание | Колонка БД |
| :--- | :--- | :--- | :--- | :--- |
| `applicationId` | string | При успехе | Идентификатор заявки | `app_id` |
| `decision` | string | Всегда | `ACCEPTED` или `REJECTED_INPUT` | `decision_code` |
| `principal` | string | При успехе | Сумма кредита | `principal_kzt` |
| `termMonths` | string | При успехе | Срок в месяцах | `term_months` |
| `errorDetail` | string | При отклонении | Текст причины отклонения | — |

### Коды ответов HTTP

**201.** Заявка успешно зарегистрирована.
```json
{"applicationId":"LN-8821","decision":"ACCEPTED","principal":"500000","termMonths":"12"}
```
или при неверных параметрах:
```json
{"decision":"REJECTED_INPUT","errorDetail":"Сумма выходит за пределы тарифа"}
```

**400.** Некорректный формат запроса.
**401.** Отсутствует или просрочен токен доступа.
**403.** Учётная запись клиента заблокирована.
**500.** Внутренняя ошибка шлюза.

#### 403. Доступ ограничен
Если учётная запись заблокирована комплаенсом, сервис возвращает HTTP **422** с пустым кодом ошибки:
```json
{"errorDetail":"Заявка не может быть обработана"}
```
