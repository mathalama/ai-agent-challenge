## Файлы

- [report.md](report.md) — отчёт на русском.
- [report.json](report.json) — тот же отчёт в JSON, схема в [docs/api/report.schema.json](../docs/api/report.schema.json).
- [trace.json](trace.json) — прогон с нуля на `v1.0.0`: стадии, длительность и расход токенов по каждому вызову модели.
- [trace-v1.0.1.json](trace-v1.0.1.json) — прогон на `v1.0.1`, по которому собран отчёт.
- [eval.txt](eval.txt) — вывод `rs eval` на этой же модели по эталонной разметке из [eval/](../eval/).

`v1.0.1` отличается от `v1.0.0` только оформлением отчёта: «Итог» считает критичные дефекты так же, как «Сводка», а у находок детерминированных правил появился текст исправления. Промпты не менялись, поэтому ответы модели на стадиях 1–9 взяты из кэша прогона на `v1.0.0`. Стадию `clarify` модель выполнила заново, потому что ей на вход передаются находки.

## Как повторить

Заполните в `.env` ключ DeepSeek, адрес и модель.

```text
OPENAI_API_KEY=<ключ DeepSeek>
OPENAI_BASE_URL=https://api.deepseek.com
OPENAI_MODEL=deepseek-flash
OPENAI_RESPONSE_FORMAT=json_object
LLM_REQUESTS_PER_MINUTE=60
```

Соберите агента с тега и запустите проверку.

```sh
git checkout v1.0.1
cargo run --release -p cli -- check samples/requirements.md -o submission/report.md --provider openai
cargo run --release -p cli -- check samples/requirements.md -o submission/report.json --provider openai
```

Вторая команда берёт ответы модели из кэша `.cache/llm/` и выдаёт тот же прогон в JSON. Новый прогон без кэша может отличаться формулировками: ответы модели недетерминированы.

## Качество на эталонной разметке

| Модель | Найдено дефектов (recall) | Precision | Покрытие вопросов |
| --- | --- | --- | --- |
| deepseek-flash | 88,9% (24/27) | 27,9% | 88,9% (16/18) |
| deepseek-v4-pro | 74,1% (20/27) | 29,4% | 83,3% (15/18) |
| gemini-3.1-flash-lite | 70,4% (19/27) | 38,0% | 50,0% (9/18) |
| gemini-3.5-flash-lite | 55,6% (15/27) | 31,9% | 38,9% (7/18) |

Эталон размечен на двух документах: документ организаторов (у `deepseek-flash` найдено 12 из 14 дефектов) и «Онлайн-заявка на потребительский кредит» (12 из 13). Метрики сняты на `db8f37d`. Изменения `v1.0.1` не меняют состав находок, но вопросы в отчёте сгенерированы заново и могут немного отличаться от тех, по которым считалось покрытие. Precision — нижняя оценка: находка вне эталона считается ложной, даже если описывает реальный дефект. Поэтому для сдачи выбрана модель с наибольшим recall и покрытием вопросов.
