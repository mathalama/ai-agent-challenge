# Правила для ИИ-агентов

Файл для любого агента: Claude Code, Codex, Gemini CLI, OpenCode и других. Идёт хакатон, дедлайн 27.11.2026 23:59. Цель: быстро довести задачу до рабочего PR, не ломая `main`.

## Режим работы

- Одна задача = одна ветка = один небольшой PR. Делай ровно то, что просили.
- Не рефактори, не переименовывай и не «улучшай» код вне задачи. Замеченное запиши в описание PR в раздел «Заметки».
- Не задавай вопросов, если можешь продолжить сам. Выбери разумный вариант и укажи допущение в PR. Спрашивай только когда без ответа работа встанет или решение меняет архитектуру.
- Не исследуй весь репозиторий. Начни с карты ниже и читай только нужные файлы.
- Не пиши длинных планов и отчётов. Код, проверка, PR.
- Если застрял на одном и том же больше двух попыток, остановись и опиши проблему, а не перебирай варианты дальше.

## Карта репозитория

- `crates/doc` — разбор документа требований в блоки с номерами строк.
- `crates/llm` — провайдеры (Gemini, OpenAI-совместимые, mock), настройки, кэш, повторы, лимиты, JSON Schema.
- `crates/review` — конвейер стадий проверки, детерминированные правила, доменные типы, отчёт, eval.
- `crates/agent` — сборка провайдера, запуск проверки и общее ядро сессии для CLI и HTTP.
- `crates/server` — HTTP API, сессии с событиями SSE, раздача `web/dist`.
- `crates/cli` — бинарь `rs`: команды `check`, `ask`, `eval`, `chat`, `serve`, `config`, `schema`.
- `web/` — веб-интерфейс на React и Vite.
- `prompts/` — промпты стадий с вызовом модели и чата, подключаются через `include_str!`.
- `dictionaries/` — словари (размытые формулировки).
- `samples/requirements.md` — документ организаторов для прогона.
- `eval/` — эталонная разметка.
- `docs/architecture.md`, `docs/decisions.md` — читай, только если задача затрагивает архитектуру.

## Проверка перед PR

Запускай проверки только для затронутых крейтов, весь workspace — если менял общие типы или несколько крейтов.

```sh
cargo fmt --all
cargo clippy -p <crate> --all-targets -- -D warnings
cargo test -p <crate>
cargo run -p cli -- check samples/requirements.md -o reports/report.md --provider mock
```

Последняя команда обязательна, если менялись `review`, `llm`, `cli` или `prompts/`. Задача готова, когда всё зелёное.

## Запреты

- Не вызывай настоящий Gemini в тестах и проверках, используй `--provider mock`.
- Не коммить `.env`, ключи, `reports/*`, `.cache/`, `target/`.
- Не добавляй зависимости без необходимости. Новую зависимость объявляй в `[workspace.dependencies]` и объясни в PR.
- Не трогай `Cargo.lock` вручную.
- Не делай `git push --force` в `main` и не мержи PR сам.
- Не отключай и не удаляй тесты, чтобы проверка прошла.

## Git и PR

- Ветка: `<тип>/<кратко>`, например `fix/verify-quotes` или `feat/json-report`.
- Коммит и заголовок PR: одна строка в повелительном наклонении на английском, как в истории репозитория, например `Add JSON report format`.
- Не вписывай имя агента или модели (Claude, Codex, Gemini и т. п.) в название ветки, сообщение коммита и описание PR. Не добавляй строки `Co-Authored-By` и подписи вроде «Generated with …».
- Описание PR по шаблону `.github/pull_request_template.md`, по 1–3 строки на раздел. В «Как проверено» перечисли запущенные команды.
- Тексты отчёта, промпты и документацию пиши на русском, как в остальном проекте.

## Ревью PR

- Ревьюер не запускает тесты, сборку и прогоны. Проверки уже сделал автор, их список есть в «Как проверено». Ревьюер доверяет этому списку.
- Ревью только по диффу: корректность логики, ошибки, граничные случаи, соответствие задаче и этим правилам.
- Не проси переделок по вкусу и стилю, если код рабочий. Мелочи помечай как необязательные.
- Если в «Как проверено» нет команд, это единственный повод вернуть PR без ревью кода.
