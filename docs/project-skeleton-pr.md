# Каркас локального Rust-агента проверки ТЗ

Ветка `chore/project-skeleton`, целевая ветка `main`.

Добавлены четыре крейта, CLI, парсеры Markdown и TXT, контракты LLM, девять стадий и рендеринг отчёта. Сквозной mock-прогон проверяет связку от исходного файла до отчёта и трассы без ключа. Границы крейтов позволяют развивать парсеры, проверки и Gemini-клиент отдельными изменениями.

Локальные проверки включают форматирование, Clippy и тесты workspace.

## Предлагаемые задачи

### Подключить Gemini API

Отправлять системный промпт, текст и JSON Schema через Gemini API. Разбирать структурированный ответ, имя модели и расход токенов.
Готово, когда успешный запрос даёт типизированный ответ, а тестовые 429 и 5xx доходят до механизма повторов.

### Реализовать парсер PDF

Извлекать текст по страницам и искать цитаты с учётом номера страницы. Обработать документы без текстового слоя.
Готово, когда тестовый многостраничный PDF даёт блоки со стабильными диапазонами, а скан получает понятную ошибку.

### Реализовать парсер DOCX

Извлекать заголовки, абзацы, списки и таблицы в порядке документа.
Готово, когда контрольный DOCX даёт ожидаемые блоки, а испорченный файл возвращает типизированную ошибку.

### Реализовать нарезку требований (`segment`)

Выделять отдельные требования в абзацах, списках и таблицах. Сохранять часть документа, исходный ID и цитату.
Готово, когда тест на размеченном фрагменте проверяет состав требований, последовательность ID и координаты.

### Извлечь факты (`facts`)

Привести сущности, единицы измерения, интервалы и условия к структурированным фактам.
Готово, когда примеры числовых границ и условий дают ожидаемые факты с цитатами.

### Добавить формальные проверки (`rules`)

Подключить первые проверки формулировок через `CheckRegistry`. Возвращать ID правила и фрагмент источника.
Готово, когда у каждого правила есть срабатывающий и несрабатывающий пример.

### Проверять каждое требование (`requirement_checks`)

Применить характеристики отдельного требования и релевантные критерии IEEE 830. Сохранять замечания со ссылкой на ID требования.
Готово, когда тестовый плохой пример для каждого подключённого критерия даёт замечание с объяснением.

### Проверять набор требований (`set_checks`)

Реализовать проверки полноты, согласованности, выполнимости, понятности и валидируемости набора. Добавить релевантные проверки IEEE 830.
Готово, когда контрольные наборы дают ожидаемые замечания области `Set` со ссылками на текст.

### Сопоставлять требования (`consistency`)

Использовать факты для поиска конфликтующих ограничений, условий и событий. Привязывать замечание к обеим сторонам.
Готово, когда примеры совместимых ограничений и противоречий дают разные результаты и два источника для конфликта.

### Находить неоднозначности (`ambiguity`)

Отмечать формулировки с несколькими прочтениями и приводить конкретные варианты интерпретации.
Готово, когда проверка различает двусмысленный и однозначный примеры и прикладывает цитату.

### Расширить сверку доказательств (`verify`)

Сохранять причину отклонения цитаты и сверять постраничные координаты PDF после появления парсера.
Готово, когда тесты проверяют верную цитату, ошибочные координаты и цитату на другой странице.

### Генерировать уточняющие вопросы (`clarify`)

Выводить вопросы по подтверждённым замечаниям, связывать их с ID и назначать приоритет.
Готово, когда тестовый набор дефектов даёт вопросы с ожидаемыми связями и приоритетом.

### Добавить русские словари

Разметить размытые слова и выражения, описать формат и правила сопоставления.
Готово, когда словарь загружается, а тесты покрывают границы слов и контекстные исключения.

### Реализовать интерактивную команду `ask`

Выводить вопросы в терминале и сохранять структурированные ответы.
Готово, когда сценарий со стандартным вводом сохраняет ответы по ID и корректно обрабатывает завершение ввода.

### Добавить эталонную разметку и команду `eval`

Разметить дефекты тестового ТЗ со ссылками на строки и критерии. Сравнить результаты агента с эталоном и вывести метрики.
Готово, когда команда читает эталон, воспроизводимо считает precision и recall и сообщает ошибку для некорректной разметки.
