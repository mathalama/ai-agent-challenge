# Архитектурные решения

## 001. Rust workspace и локальный CLI

Один бинарь принимает пути исходного документа и отчёта. Парсинг, доступ к модели и проверка качества вынесены в отдельные библиотеки с однонаправленными зависимостями.

## 002. Типизированные данные на границе модели

Стадии описывают ожидаемый ответ Rust-типами. Из типов строится JSON Schema. Ответ проходит десериализацию, а подтверждение цитат и сводка выполняются кодом.

## 003. Mock для сквозного прогона

Mock возвращает заранее определённую форму ответа для каждой стадии. Для проверки передачи координат `segment` использует один блок из входного документа. Вывод mock-прогона явно отмечает, что оценка готовности ещё не проведена.

## 004. Локальные результаты и версия сборки

Отчёт, опциональная трасса и кэш записываются локально. Версия в паспорте берётся из короткого хеша Git и точного тега, если он есть. При сборке без доступного коммита указывается `unknown`.
